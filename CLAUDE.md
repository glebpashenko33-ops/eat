# Радар: расширения 1С в существующих базах

Здесь ИИ-агент пишет новые расширения и исправляет существующие в реальных базах 1С. Основная конфигурация баз не меняется никогда: вся работа идёт только через расширения.

Команды:
- `/1c-base add | refresh | list` — подключить базу, забрать её актуальное состояние, показать список.
- `/1c-task <задача>` — исправление или доработка от текста задачи до загруженного и проверенного расширения.
- `/1c-rollback <Расширение>` — вернуть расширение к бэкапу.

## Структура

| Путь | Что это | В git |
|---|---|---|
| `bases/<id>/cf/` | XML-выгрузка основной конфигурации базы, только для чтения и анализа | нет |
| `bases/<id>/cfe/<Имя>/` | Исходники расширений базы | да |
| `bases/<id>/backup/` | `.cfe`-бэкапы расширений перед каждой загрузкой | нет |
| `bases/<id>/NOTES.md` | Память о базе: конфигурация, версия, расширения и их назначение | да |
| `bases/<id>/bsl-analyzer.toml` | Конфиг анализатора, генерирует `radar.ps1` | нет |
| `.v8-project.json` | Реестр баз: подключение, пароли, `protected`, расширения | нет |
| `.mcp.json` | MCP-сервер `bsl`, генерирует `radar.ps1` | нет |

Текущая база — `default` в `.v8-project.json`. Её выбирает `.\radar.ps1 <id>`, и MCP-сервер `bsl` анализирует именно её выгрузку.

## Инструменты

- **MCP `bsl`** (bsl-analyzer по выгрузке текущей базы): `metadata` — объекты, реквизиты, формы; `search` — поиск по коду и по справке платформы; `symbol_info`, `graph` — где определён метод и кто его вызывает, включая расширения; `syntax_help` — синтакс-помощник; `diagnostics` — ошибки и замечания по коду; `outline` — структура модуля; `query` `validate` — проверка запросов. Работает без подключения к базе.
- **Навыки `.claude/skills/`** (cc-1c-skills): `/cfe-init`, `/cfe-borrow`, `/cfe-patch-method`, `/cfe-validate`, `/cfe-diff` — расширения; `/form-*`, `/mxl-*`, `/skd-*`, `/role-*` — формы, макеты, СКД, роли; `/db-dump-xml`, `/db-dump-cf`, `/db-load-xml`, `/db-load-cf`, `/db-update`, `/db-cfe-admin`, `/db-repo`, `/db-run` — работа с базой.

## Правила безопасности

- **Основную конфигурацию базы не меняй никогда.** Навыки `/db-load-xml`, `/db-load-cf` и `/db-update` вызывай только с `-Extension <Имя>`. Не вызывай `/db-load-dt`, `/db-create` и `/db-cfe-admin delete` для зарегистрированных баз без прямой просьбы пользователя в этом сообщении.
- **Перед каждой загрузкой расширения делай его бэкап** (`/db-dump-cf ... -Extension`) в `bases/<id>/backup/`. Нет бэкапа — нет загрузки (кроме самой первой загрузки нового расширения).
- **`protected: true`** (рабочая база с пользователями): перед загрузкой покажи, что меняется, и дождись явного подтверждения с именем базы. Обновляй с `-Dynamic on`.
- Работай с базой, названной в задаче, или с текущей. Если задача явно про другую базу, переспроси перед загрузкой.
- Данные в базах не меняй: никаких записей ради проверки.
- Правки делай поверх актуального состояния: перед изменением перевыгрузи расширение из базы и закоммить расхождения отдельно.
- Пароли из `.v8-project.json` не выводи в ответах и не коммить.

## Правила расширений

- Исправление ошибки типовой — расширение с назначением `Patch`, доработка — `Customization`. Не смешивай несвязанные задачи в одном расширении без согласия пользователя.
- Заимствуй минимум: только объекты и методы, которые реально меняешь.
- Перехваты: `&Перед` и `&После` — по умолчанию; `&ИзменениеИКонтроль` — когда нужно поменять сам типовой код; `&Вместо` — только если иначе нельзя, с объяснением.
- Новые объекты, реквизиты, методы, элементы форм — с префиксом расширения.
- Режим совместимости расширения — как у основной конфигурации (`/cfe-init` с `-ConfigPath` берёт его сам).

## Правила кода BSL

- Русский синтаксис, стандарты 1С (its.1c.ru/db/v8std).
- Директива компиляции у каждого метода формы: `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`. Один серверный вызов на действие пользователя, никаких серверных вызовов в цикле.
- Данные — запросом, а не через точку в цикле. Никаких запросов в цикле.
- Запросы: явные поля, параметры вместо склейки строк, `РАЗРЕШЕННЫЕ` для данных, которые видит пользователь, виртуальные таблицы остатков и оборотов с параметрами, а не отбор в `ГДЕ`.
- Без модальных вызовов: `Асинх` и `Ждать` или `ОписаниеОповещения`.
- В типовых сначала ищи механизм БСП (печать, подключаемые команды, длительные операции) и встраивайся в него.
- Метод платформы, в котором не уверен, проверь через `syntax_help`. Не выдумывай методы и свойства.
- Экспортные методы — с комментарием по стандарту: описание, `Параметры:`, `Возвращаемое значение:`.

## Готово, когда

`/cfe-validate` и `/cfe-diff` без ошибок, `diagnostics` без ошибок по изменённым модулям, запросы прошли `query validate`, в базе `/db-cfe-admin check -Checks apply,modules` без ошибок, изменения закоммичены, пользователь получил инструкцию, как проверить руками. Если проверка не проходит после 3 попыток исправления, остановись и опиши проблему, а не обходи её.
