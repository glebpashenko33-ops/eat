# Радар: агентная разработка на 1С

Проект — рабочее место, где ИИ-агент делает доработки 1С по задаче, написанной обычным текстом: изучает конфигурацию, пишет код, собирает результат, обновляет базу разработки и проверяет его тестами и запросами. Основной сценарий — команда `/1c-task <задача>`.

## Структура

| Путь | Что это |
|---|---|
| `src/cf/` | XML-выгрузка конфигурации базы разработки (DumpConfigToFiles) |
| `src/cfe/<Имя>/` | Исходники расширений, в том числе расширения с тестами YAxUnit |
| `src/epf/`, `src/erf/` | Исходники внешних обработок и отчётов |
| `build/` | Собранные `.epf`, `.erf`, `.cfe` |
| `tools/` | Скачанные инструменты и `metr.yml` (не в git) |
| `.v8-project.json` | Платформа и база для навыков cc-1c-skills (не в git, есть пароли) |
| `.mcp.json` | MCP-серверы (не в git, генерируется `setup/install.ps1`) |
| `config/radar.json` | Исходные настройки машины (не в git) |

## Инструменты

| MCP-сервер | Для чего |
|---|---|
| `onec-base` | Метаданные, структура объектов и форм, поиск по коду выгрузки, `validate_query` и `execute_query` (только чтение) на базе `dev`, журнал регистрации |
| `onec-help` | Синтакс-помощник платформы: типы, методы, свойства, конструкторы |
| `onec-tests` | Сборка и обновление базы `dev`, синтаксический контроль, запуск тестов YAxUnit |
| `bsl-check` | Статический анализ BSL (bsl-analyzer) |

Навыки `.claude/skills/` (cc-1c-skills) работают с XML-форматами 1С и пакетным режимом конфигуратора: обработки, отчёты, формы, макеты, СКД, роли, расширения, загрузка и выгрузка, веб-публикация, проверка через веб-клиент.

## Правила безопасности

- Работай только с базой `dev` из `.v8-project.json`. Никогда не подключайся к рабочей базе, даже если пользователь назвал её путь в задаче: сначала переспроси.
- `execute_query` — только `ВЫБРАТЬ` и всегда с `ПЕРВЫЕ N`. Никаких записей в базу через запросы, обработки или консоль кода ради проверки.
- Объекты на поддержке не меняй: доработку делай в расширении. Если без снятия с поддержки никак, остановись и спроси.
- Не коммить `.v8-project.json`, `.mcp.json`, `config/radar.json`, `tools/`, `build/`, `logs/`.
- Не выводи пароли из конфигов в ответах и логах.
- Не мержи в `main` сам: ветку принимает человек.

## Правила кода BSL

- Язык — русский синтаксис 1С. Стандарты разработки 1С (its.1c.ru/db/v8std) обязательны.
- Директиву компиляции указывай у каждого метода формы явно: `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`. Минимизируй серверные вызовы: один вызов на действие пользователя, а не вызов в цикле.
- Данные читай запросом, а не через точку в цикле. Не выполняй запросы в цикле: собери параметры и сделай один пакетный запрос.
- Запросы пиши с явными полями (без `*`), с параметрами вместо подстановки строк, с `РАЗРЕШЕННЫЕ` там, где пользователь видит данные. Для остатков и оборотов используй виртуальные таблицы с параметрами, а не отбор в `ГДЕ`.
- Модальные вызовы запрещены: используй `Асинх` и `Ждать` или `ОписаниеОповещения`.
- Для типовых конфигураций сначала ищи готовый механизм БСП (печать, дополнительные отчёты и обработки, длительные операции) и встраивайся в него.
- Новые объекты и методы в расширениях — с префиксом расширения.
- Перед использованием метода платформы, в котором не уверен, проверь его в `onec-help`. Не выдумывай методы и свойства.
- Каждый экспортный метод — с комментарием в формате стандарта: описание, `Параметры:`, `Возвращаемое значение:`.

## Порядок работы

1. Исследуй, потом пиши: метаданные и похожий код через `onec-base`, API платформы через `onec-help`.
2. Меняй исходники через навыки, а не ручной правкой XML.
3. После изменения `src/cf` или расширений собери проект (`onec-tests` `build_project`) и обнови индекс (`onec-base` `reload_dump`).
4. Результат считается готовым, только когда: валидация навыками без ошибок, `bsl-check` без ошибок, все запросы прошли `validate_query` и дали правдоподобный результат в `execute_query`, сборка и синтаксический контроль успешны, тесты YAxUnit зелёные.
5. Если проверка не проходит после 3 попыток исправления, остановись и опиши проблему, а не обходи её.
