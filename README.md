# Радар

Рабочее место для агентной разработки на 1С:Предприятие 8.3. Задачу пишут обычным текстом, ИИ-агент (Claude Code) сам изучает конфигурацию, пишет код, собирает результат, обновляет базу разработки и проверяет его. Человек проверяет итог и принимает ветку.

```
/1c-task сделай отчёт по просроченной дебиторке
```

## Как это работает

| Шаг | Что делает агент | Чем |
|---|---|---|
| 1. Задача | Разбирает текст, задаёт до 3 уточняющих вопросов, выбирает вид результата | команда `/1c-task` |
| 2. Изучение | Смотрит метаданные и похожий код в конфигурации, сверяет методы со справкой платформы | MCP [mcp-1c](https://github.com/feenlace/mcp-1c), [mcp-bsl-platform-context](https://github.com/alkoleft/mcp-bsl-platform-context) |
| 3. Разработка | Пишет BSL и XML, собирает `.epf`/`.erf`, расширение, форму, макет, СКД без Конфигуратора | навыки [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) |
| 4. Проверка | Линтер, проверка и выполнение запросов на базе `dev`, сборка и обновление базы, синтакс-контроль, тесты YAxUnit, при желании прогон через веб-клиент | [bsl-analyzer](https://github.com/itrous/bsl-analyzer), mcp-1c, [mcp-onec-test-runner](https://github.com/alkoleft/mcp-onec-test-runner), [YAxUnit](https://github.com/bia-technologies/yaxunit) |
| 5. Сдача | Коммитит в ветку `task/...` и пишет отчёт: что сделано, как проверено, риски | git |

Правила для агента (безопасность, стандарты кода, критерии готовности) лежат в [`CLAUDE.md`](CLAUDE.md), конвейер — в [`.claude/commands/1c-task.md`](.claude/commands/1c-task.md).

## Что нужно

- Windows 10/11 с PowerShell 5.1+.
- Платформа 1С:Предприятие 8.3 (лучше 8.3.27) с Конфигуратором.
- **Отдельная база для разработки.** Агент обновляет её конфигурацию, рабочую базу не подключайте.
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code), Git, Java 17+, Python 3.9+. Node.js 18+ — для проверки через веб-клиент (необязательно).

## Установка

1. Склонируйте репозиторий и скопируйте настройки:

   ```powershell
   git clone https://github.com/glebpashenko33-ops/radar.git
   cd radar
   copy config\radar.example.json config\radar.json
   ```

2. Заполните `config\radar.json`:

   | Поле | Что указать |
   |---|---|
   | `platformPath` | Каталог версии платформы, например `C:\Program Files\1cv8\8.3.27.1688` |
   | `infobase` | `type`: `file` (+ `path`) или `server` (+ `server`, `ref`); пользователь и пароль 1С |
   | `webAppName`, `webPort` | Имя и порт веб-публикации базы (по умолчанию `dev` и `8081`) |
   | `httpUser`, `httpPassword` | Пользователь для HTTP-сервиса, если публикация требует авторизации |
   | `builder` | `DESIGNER` или `IBCMD` — чем собирать базу |
   | `testsExtension` | Имя расширения с тестами (по умолчанию `Tests`) |

3. Запустите установщик. Он скачает инструменты, поставит навыки, выгрузит конфигурацию в `src\cf` и сгенерирует `.mcp.json`, `.v8-project.json` и `tools\metr.yml`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File setup\install.ps1 -DumpConfig
   ```

4. Запустите Claude Code в каталоге проекта, разрешите MCP-серверы проекта и один раз подготовьте базу:

   ```powershell
   claude
   ```

   ```
   /1c-bootstrap
   ```

   Команда поставит в базу расширение mcp-1c, опубликует её через портативный Apache, загрузит YAxUnit и создаст расширение с примером теста. После неё перезапустите Claude Code.

5. Работайте:

   ```
   /1c-task добавь в документ «Реализация товаров и услуг» печатную форму «Акт сверки» по макету из вложения
   ```

## Ключи установщика

| Ключ | Что делает |
|---|---|
| `-DumpConfig` | Выгрузить конфигурацию базы в `src\cf` (перезапишет имеющуюся выгрузку) |
| `-ConfigOnly` | Только перегенерировать конфиги, ничего не скачивая |
| `-SkipDownload` | Не скачивать инструменты повторно, но поставить навыки и сгенерировать конфиги |
| `-Config <путь>` | Другой файл настроек вместо `config\radar.json` |

## Замечания

- **Выгрузка в git.** `src\cf` коммитится, чтобы изменения агента были видны в диффе. Для больших типовых конфигураций (ERP, КА) первый коммит будет тяжёлым. Если это мешает, добавьте `src/cf/` в `.gitignore` и держите в git только расширения и внешние обработки.
- **Разрешения.** При первом вызове каждого MCP-инструмента Claude Code спросит разрешение. Чтобы не подтверждать безопасные инструменты каждый раз, добавьте их в `permissions.allow` в `.claude/settings.local.json` (например, `mcp__onec-help` и `mcp__onec-base__get_metadata_tree`).
- **Платные функции mcp-1c.** Здесь используется бесплатная открытая версия (MIT). У автора есть платные редакции с линтером, синтакс-помощником и семантическим поиском, они не обязательны.
- **Модель.** По бенчмаркам [PRISM](https://prism.genlab-1c.ru/) и [1C Code Bench](https://1cbench.github.io/) код 1С лучше всего пишут старшие модели Claude. Отправка кода во внешний сервис должна быть согласована с владельцем конфигурации.
